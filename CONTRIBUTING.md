# Contributing

1. Work through a feature branch and pull request.
2. Keep each product independently testable.
3. Use synthetic data and generic organization names.
4. Add acceptance criteria, tests and evaluation cases with every material feature.
5. Record architecture decisions under the relevant product.
6. Document human-review, escalation and excluded-decision boundaries.
7. Do not include confidential or third-party restricted source material.
8. Prefer standards-based, vendor-neutral interfaces.

## Commit convention

Use `type(scope): summary`, for example:

- `feat(strategic-radar): add source approval workflow`
- `test(ipsas): add recognition-rule evaluation cases`
- `docs(governance): define human approval matrix`
