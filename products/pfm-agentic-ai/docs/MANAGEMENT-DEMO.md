# P01 Management Demo — Hybrid Live/Synthetic Product

## Purpose

The management-demo release demonstrates how governed agentic AI can support the end-to-end public finance management cycle without representing unapproved demo data as real government financial information.

The product deliberately separates four evidence classes:

1. **LIVE EXTERNAL** — successfully retrieved public evidence from configured authoritative sources.
2. **SIMULATED INTERNAL** — coherent synthetic entity, budget, revenue, treasury, cash and accrual data.
3. **AI INFERENCE** — interpretation, scenario analysis, management explanation and recommendation.
4. **APPROVAL REQUIRED** — protected actions that remain with the authorized government official.

A failed external source never falls back to a fake live signal. It is displayed as degraded/unavailable.

## Management experience

### Signals & Outlook

An animated fiscal radar displays verified live public signals. Selecting a signal shows source, fact, retrieval status, confidence, materiality, fiscal exposure and the separation between evidence and AI interpretation. The impact chain is:

`Live signal → AI interpretation → scenario hypothesis → synthetic fiscal impact → analyst/authority validation`

### Agent Workflow

The workflow/orb view demonstrates the governed handoff across Signal Intelligence, Fiscal Strategy, Budget Execution, Entity Monitoring, Cash Forecasting, Authority Gate and Accounting. Runtime events show what an agent did and whether the state is running, exception or waiting for approval.

### Budget & Entities

Five synthetic government entities use one internally coherent fiscal model: approved/adjusted budget, actual, commitments, accrual, cash paid, forecast, monthly funding request, modelled cash need, delay exposure and risk.

### Treasury & Cash

The liquidity horizon shows 7/30/60/90-day synthetic positions. Entity funding requests are compared with modelled need, but the platform does not release funds. Material requests terminate at a Treasury approval gate.

### Accounting & Consolidation

The budget/cash/accrual bridge explains timing differences and supports reconciliation analysis. It is explicitly not a certified financial statement.

### Ask PFM

The executive query interface answers a controlled set of fiscal questions from the same synthetic data model and returns evidence labels, confidence and a management recommendation. It does not invent access to real FMIS/GRP data.

### Report Factory

Reports can be generated by type, entity, mandate and period. Current report types cover budget execution, entity position, expenditure, revenue, cash forecast, delays, accounting close, fiscal risk and consolidation. Every generated report is labelled `EVIDENCE_LINKED_DRAFT` and `SIMULATED_INTERNAL`.

## Demo scenarios

- `baseline` — normal fiscal pulse.
- `revenue_shock` — reduces synthetic revenue forecast and liquidity outlook while leaving the approved revenue plan unchanged.
- `capital_delay` — increases Entity C delay exposure and forecast overrun.
- `cash_pressure` — raises Entity C funding request and triggers an authority gate.
- `close_exception` — creates month-end reconciliation and consolidation readiness exceptions.
- Reset restores the baseline before each management presentation.

## Live-source adapters

The server uses standard-library HTTPS retrieval so no API key is required for the baseline public-source demo. Baseline adapters include:

- World Bank Indicators API for UAE macro indicators.
- IMF public News page for global macro-policy headlines.
- Government of Dubai Media Office public page for local government-direction headlines.

Additional approved public sources can be configured with `PFM_SIGNAL_SOURCES_JSON`. Each object requires `name`, `url`, and optional `scope` and `limit`.

Example:

```json
[
  {"name":"Approved Authority","url":"https://example.gov/news","scope":"LOCAL","limit":2}
]
```

Production should replace generic page extraction with source-specific API/RSS contracts, evidence snapshots/hashes, retention rules and monitoring.

## Run

From repository root:

```bash
cp products/pfm-agentic-ai/deploy/.env.example products/pfm-agentic-ai/deploy/.env
docker compose -f products/pfm-agentic-ai/deploy/docker-compose.yml up --build -d
```

Open `http://localhost:8080/` for the management demo. Open `/docs` for the API. `/command-center` exposes the separate configurable agent command-center prototype.

## Management demonstration sequence

1. Refresh Signals and open one authoritative source.
2. Explain Fact versus AI Interpretation.
3. Apply `revenue_shock` and animate the workflow.
4. Open Entity C and explain budget/forecast/delay/cash pressure.
5. Show Treasury approval interruption.
6. Show budget/cash/accrual bridge.
7. Ask: `Show delayed projects with high cash requests`.
8. Generate an Entity Fiscal Position or Fiscal Risk report.
9. Reset the demo.

## Production boundary

This release is a functional management-demo product. It is **not** production authorization to process government financial transactions. Production integration requires approved identity/RBAC, delegations, segregation of duties, authoritative data contracts, secure source-system interfaces, audit/evidence persistence, legal/accounting/security review, reconciliation, UAT and formal go-live approval.
