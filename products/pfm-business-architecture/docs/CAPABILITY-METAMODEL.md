# Capability metamodel

Each capability has a stable ID, name, L1 domain, owner, mandate, value-chain stage, process/service references, information objects, systems, KPIs, risks, controls, evidence, maturity, criticality and optional PEFA/IPSAS tags.

Empty required fields lower coverage; unknown mandate/evidence IDs create exceptions. System references describe patterns only. Capability owners and design authority control lifecycle, approval and publication.
