# Information Handling and Confidentiality

## Prohibited repository content

Do not commit:

- Government or employer-confidential information.
- Real budgets, transactions, revenues, forecasts, chart-of-account extracts, audit findings, risks, controls, agreements, personal data, or security records.
- Internal system credentials, tokens, URLs, infrastructure identifiers, source documents, screenshots, meeting records, or unapproved policies.
- Proprietary third-party software exports or copyrighted reference material without permission.
- Organization names, internal cost figures, vulnerabilities, or vendor correspondence unless explicitly approved for disclosure.

## Permitted content

- Generic product requirements and reference architectures.
- Synthetic datasets clearly labelled as synthetic.
- Public standards referenced by name without reproducing protected content.
- Sanitized prompts, schemas, controls, test cases, and code.
- User-created intellectual property only where repository storage is authorized.

## Classification labels

| Label | Meaning | Repository treatment |
|---|---|---|
| PUBLIC | Approved for public release | May be moved to a public repository |
| PORTFOLIO-INTERNAL | Personal/private product material | Allowed in this private repository |
| RESTRICTED-SOURCE | Internal or third-party source artifact | Register metadata only; do not commit |
| SECRET | Credentials or security secrets | Never commit |
| PERSONAL-DATA | Identifiable information | Never commit without a lawful approved process |

## Data onboarding gate

A product may move beyond synthetic data only after data ownership, legal basis, classification, minimization, retention, access control, security testing, audit logging and human-approval requirements are documented and approved.
