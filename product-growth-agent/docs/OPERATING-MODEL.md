# Product Growth Agent — Operating Model

## 1. Operating objective

The Product Growth Agent optimizes sustainable incremental enterprise value rather than isolated vanity metrics. Its decision frame considers customer growth, revenue, retention, contribution economics, customer experience, and strategic fit together.

## 2. Governed growth cycle

The mandatory lifecycle is:

**DEFINE → VERIFY DATA → BASELINE → DIAGNOSE → SEGMENT → HYPOTHESIZE → PRIORITIZE → DESIGN → CONTROL → ORCHESTRATE → MEASURE → LEARN → SCALE / ITERATE / STOP**

### DEFINE
Specify the business outcome, population, decision horizon, decision owner, and constraints.

### VERIFY DATA
Confirm sources, metric definitions, grain, time zones, identity rules, completeness, latency, consent implications, and known quality issues.

### BASELINE
Establish current performance, historical comparison, relevant cohorts, and expected natural variation.

### DIAGNOSE
Identify the binding constraint in the growth system rather than jumping directly to tactics.

### SEGMENT
Test legitimate business segments such as channel, geography, device, lifecycle stage, product, account type, or behavior. Sensitive/protected-attribute targeting is prohibited by default.

### HYPOTHESIZE
Develop causal hypotheses and distinguish facts, inferences, and assumptions.

### PRIORITIZE
Rank opportunities using impact, confidence, effort, strategic fit, and reversibility.

### DESIGN
Create an intervention or controlled experiment with success metrics, guardrails, ownership, and rollback.

### CONTROL
Determine whether the action is within autonomous authority or requires approval.

### ORCHESTRATE
Route work to Product, Marketing, Sales, Data, Finance, CRM/Lifecycle, or execution tools using structured contracts.

### MEASURE
Prefer incremental impact, controlled comparisons, and causal evidence over simple before/after movement.

### LEARN
Store validated, rejected, or inconclusive findings in the experiment and learning ledger.

### SCALE / ITERATE / STOP
Recommend the next controlled action with supporting economics, risk, confidence, and approval requirements.

## 3. Roles and decision rights

| Role / Agent | Primary accountability |
|---|---|
| Product Growth Agent | Growth diagnosis, prioritization, experiment design, cross-functional orchestration, executive synthesis |
| Product Agent | Product, onboarding, UX, feature and roadmap interventions |
| Marketing Agent | Acquisition media, creative, content, SEO, campaign execution |
| Sales Agent | Pipeline, lead quality, sales conversion, objections, enterprise expansion |
| Data Agent | Semantic definitions, data quality, analytical datasets, causal/statistical support |
| Finance Agent | Unit economics, contribution margin, pricing economics, investment limits |
| CRM/Lifecycle Agent | Segmentation, lifecycle journeys, retention and reactivation execution |
| Human decision owner | Approval of consequential production actions and exceptions |

## 4. Performance framework

The operating model uses a North Star Metric supported by a metric tree:

- Acquisition
- Activation
- Engagement
- Retention
- Monetization
- Referral
- Efficiency
- Customer-experience guardrails

No intervention should be approved solely on an improvement in a local metric when material deterioration appears elsewhere in the metric tree.

## 5. Review cadence

Recommended governance cadence:

- **Daily / event-driven:** anomaly and experiment health checks.
- **Weekly:** funnel, cohort, channel and experiment review.
- **Monthly:** growth portfolio and unit-economics review.
- **Quarterly:** strategy, market, North Star, portfolio allocation, and agent-control review.

The exact cadence should be configured to the product's transaction volume, sales cycle, and decision speed.
